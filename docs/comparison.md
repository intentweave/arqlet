# Comparison with external layout engines

Status: first parity harness, 15 demo and synthetic views, 150-node limit. Evaluation only; no code
from these engines is used by Arqlet. The harness and its pinned dependencies live in
`benchmarks/eval/`. Raw numbers: `benchmarks/results/eval-*.jsonl`. The full per-dataset tables are
in the matching `eval-*.md` (generated by `benchmarks/eval/report.py`).

## What is compared, and how

- **Input.** Every engine gets the same graph: the bounded view that Arqlet selects from each
  dataset (its connected part, up to 150 nodes). Leaf nodes are 180 × 54, the same as Arqlet's
  leaves. Containers are sized by each engine. Direction follows the view's default direction. Per-container
  directions are not mapped, because only Arqlet supports them.
- **Engines.** Arqlet (initial placement, and after refinement), `elkjs` 0.12.0 with the layered
  algorithm, orthogonal routing and hierarchy included, and `@dagrejs/dagre` 3.1.1 in compound mode. For
  dagre, the flat variant is also reported, because compound mode fails on three of the fifteen inputs.
- **Scoring.** One implementation scores every output from the same geometry: crossings between edges
  (excluding edges that share an endpoint), edge–node hits (an edge passing through a node it does not
  attach to), overlaps between leaves, bounding-box area, total edge length, the share of diagonal
  segments (non-orthogonal routing), and the mean gap between edge ends and their nodes.
- **Validity check.** Every engine's edge ends touch their nodes (endpoint gap 0 for all rows). This
  test caught a coordinate-frame error in the ELK conversion, which was corrected before the run.

## Results of 2026-10-20 (mean over 15 views)

Current run: `benchmarks/results/eval-routing-*.jsonl`, generated tables in the matching `.md`.

| engine | crossings | edge–node hits | overlaps | area | edge length | diagonal share | layout ms | views with zero edge–node hits |
|---|---|---|---|---|---|---|---|---|
| Arqlet (initial) | 421 | 189 | 0 | 3.8 M | 65 k | 0 | 40 | 0 / 15 |
| Arqlet (refined) | 379 | 3.4 | 0 | 3.8 M | 65 k | 0 | 145 | 11 / 15 |
| elkjs layered (orthogonal) | 249 | 0.3 | 0 | 7.1 M | 139 k | 0 | 52 | 12 / 15 |
| dagre, compound (12 views) | 232 | 28 | 0 | 16.3 M | 118 k | 0.3 | 92 | 4 / 12 |
| dagre, flat (15 views) | 144 | 22 | 0 | 7.3 M | 69 k | 0.4 | 23 | 4 / 15 |

**Reading the table.**
- Arqlet's refinement removes almost all edge–node hits (188 → 3.4), which is the main thing the
  routing work was for. ELK is at 0.3.
- Crossings are where Arqlet trails: 379 against 250 for ELK, and 144 for flat dagre. Part of this
  gap is routing, not ordering: see the ordering experiment below.
- The area is the smallest of the hierarchical engines, but the flat dagre variant is smaller still
  because it has no containers. Area is not a quality measure by itself.
- **Timing is not like for like.** Arqlet's figures include a process spawn and a JSON round trip.
  ELK and dagre are timed in-process. Use these numbers for orders of magnitude only.

## Ordering experiment (negative result)

I tried a crossing-objective ordering: repeated barycenter or median sweeps, keeping the best ordering by
crossing count, followed by a transposition pass. It lowers the crossings between links that join the
same pair of ranks, so it is a correct objective for layered ordering. As two extra refinement
candidates, it changed the result on only one of fifteen views (petri-net, 51 → 29 crossings), and the
mean refined crossings moved from 379 to 377 while refinement time rose about 50%. I removed it.

Why it does not transfer: refinement picks the candidate by the spec's order of priority. Node penetration
(a hard constraint) comes first, then shared route segments, then routed crossings (soft). On the
workflow DAG, the refined layout went from 906 to 6 node penetrations and from 494 to 28 shared route
pairs, while routed crossings went from 340 to 636. The crossings were traded for hard constraints, as
the spec intends. Lowering crossings therefore needs routes that avoid both, which is a routing change,
not an ordering change.

## Engine failures on these inputs

| dataset | engine | error |
|---|---|---|
| layerweave-code | dagre (compound) | `Cannot set properties of undefined (setting 'rank')` |
| state-order | dagre (compound) | `Cannot set properties of undefined (setting 'rank')` |
| uml-class | dagre (compound) | `Not possible to find intersection inside of the rectangle` |

The first two fail only when compound edges are present (a minimal case without edges passes),
which points inside dagre's compound handling. The harness records these failures and runs the flat
variant instead. Note that the flat variant has no containers, so its container metrics are not comparable.

## Parity status

Parity here means: same input, same leaf sizes, same metrics. It does not mean the same features or the same defaults.

| capability | Arqlet | elkjs layered | dagre |
|---|---|---|---|
| nested containers | yes (view-level, per-container direction) | yes (`INCLUDE_CHILDREN`) | compound mode; fails on 3 of 15 inputs here |
| explicit and automatic ports | yes (side, offset, facing sides) | yes (port constraints) | not supported |
| cycles, self-loops, parallel edges | yes (tests) | yes | yes; self-loop and parallel handling not verified in the harness |
| orthogonal routing | yes (heuristic; obstacle-aware refinement) | yes (`ORTHOGONAL`) | no (polylines) |
| incremental edits with revision checks | yes | no (full layout per call) | no |
| per-container direction | yes | not mapped in the harness | not mapped in the harness |
| hybrid direction | yes (local choice) | no | no |
| runtime in the browser | WASM worker, backend | JavaScript | JavaScript |

Not measured here: ELK's port constraints and label handling, dagre's clipping behavior beyond the
failures above, and any engine's behavior on the full 100K-node target. The parity table lists what
each engine offers, and it is written from the engines' documentation and from what the harness exercised.

## Reproduce

```sh
cargo build --release -p arqlet-runtime --bins --locked
cd benchmarks/eval && npm ci && node compare.mjs --limit 150
python3 benchmarks/eval/report.py ../results/eval-<UTC>.jsonl
```
