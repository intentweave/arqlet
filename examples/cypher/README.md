# Cypher fixtures

Test data for the Cypher query layer proposed in [ADR 0021](../../docs/adr/0021-cypher-query-layer.md), stage M0. There
is no engine yet: these files say what the engine must answer, and the oracle says where the expected answers come from.

| Path | What it is |
|---|---|
| `graphs/*.json` | Pinned copies of graphs: `small`, `layerweave-code`, `org-chart`, `network-vlan` (from `examples/fixtures/` and `benchmarks/inputs/`), and `spike`, a small graph with a cycle, a self-loop and parallel edges. `graphs/SHA256SUMS` pins them. |
| `payloads/spike.json` | A payload table for `spike`: properties (`name`, `age`, `since`) by node and edge id, as ADR 0021 item 1 of M0 defines the host-supplied table. The real graphs carry none. |
| `cases.jsonl` | One case per line: a query against a graph, its status, and the expected rows or the error class. Generated by `oracle.py`; do not edit by hand. |
| `oracle.py` | The independent oracle: plain Python, straight from the graph files, no Cypher engine. |
| `corpus.tsv` | 40 queries from the parser spike with a verdict each (below). |

```sh
python3 examples/cypher/oracle.py --write     # regenerate cases.jsonl and graphs/SHA256SUMS
python3 examples/cypher/oracle.py --check     # fail if either differs
python3 examples/cypher/oracle.py --summary   # counts per graph and status
```

## Why `layerweave-code.json` is a copy

`benchmarks/inputs/layerweave-code.json` can be regenerated by the playground build, and its contents then change. These
fixtures keep their own copy, pinned by hash, so an expected number does not move under a test. The same holds for the
other graphs.

## Cases

`status` in `cases.jsonl`:

| Status | An engine must |
|---|---|
| `supported` | return exactly `rows` (in order if `ordered` is true, otherwise as a multiset) |
| `later` | reject the query now with `error`; the construct is in ADR 0021's "Later" column. Where `rows` is present it is what the query returns once the construct is supported |
| `rejected` | reject the query with `error`; outside the first release |
| `invalid` | answer with a syntax error |
| `open` | nothing yet: the ADR is silent; decide before implementing. `rows` is recorded where it is clear |

`error` names a class (`unsupported`, `syntax`); the names are provisional. `columns` holds the source text of the return
items and is informational until the engine's column naming rule is decided. Values are JSON: integers stay integers,
`null` is null.

The cases are chosen to hit what goes wrong first: a self-loop (matched once when undirected), parallel edges,
relationship uniqueness within a pattern (`*2`, two hops), null in a filter and as an output value, grouping by a value
rather than by a node (two nodes labelled `run` form one group), type alternatives, edge types with a space (backticks),
and an unresolved edge that must not be counted. Four `later` cases are the constructs decypher 0.2 dropped silently
(upstream issues #132 to #134, fixed in 0.3); the guard must reject them until the executor runs them.

## Corpus verdicts

`corpus.tsv` columns: `parse` is what a parser must do (`ok` or `err`); `verdict` is what the layer must do under ADR
0021, item 5 (`supported`, `later`, `rejected`, `open`, `invalid`, as above). The verdict is this fixture's reading of the
ADR; where the ADR does not say, it is `open`: path variables, pattern comprehensions and predicates, quantifier
predicates, map projections, multi-label patterns and label expressions (the first function table is in the ADR,
section *The function table and UNION*). Change a verdict in review if
the ADR is clarified.

## How the expected values were checked

The oracle was cross-checked on 2026-11-21 (and again after `spike-11` moved to `later` and `spike-20` was added) against
Grafeo 0.6.2 running the same queries on a store built from the same graph and payload files (a throw-away checker, not
part of this repository): all 40 `supported` cases there were then and the four `later` or `open` cases with rows agreed. The cases `fn-*`,
`union-*`, `expr-*`, `where-*` and `repeat-*` have not been compared with Grafeo: their expectations are the oracle's alone. Changing two
expected values by hand made the checker fail, so the comparison is not vacuous. This is evidence that the oracle and an independent engine read these queries alike. It is not the openCypher
TCK, and it covers only these queries on these graphs.

## What is not here

A runner. The first engine stage (M1 to M4) writes the test that reads `cases.jsonl`, runs each case, and applies the
table above. The differential check against Grafeo is a later stage (M6) with its own tool.
