# Joint versus structured under three constraint regimes

Machine: Apple M3, 8 logical CPUs, 16 GiB, macOS 26.0. Revision: 1b38b72 (main, after #64), plus the example `structured_compare.rs` with the `REGIME` switch. Default options, one thread, one run per cell. Times are indicative.

Regimes (the root is unchanged in all three):
- **authored**: the authored container directions.
- **auto**: every container is free.
- **allowed**: every container is the allowed set [lr, tb].

Joint: the whole graph under the resolved constraints, using each constraint's default choice (free and allowed take the first orientation, lr); joint has no search. Structured: the hierarchical composition, whose shape search tries each container's allowed orientations once, root included; the winner is the better key of the composition and the joint layout.

Drawings: `benchmarks/results/regimes/index.html` shows, per diagram and regime, the joint drawing, the winner and the raw composition (SVG). The SVG drawings were not checked by eye in this run; the page is for that check.

## Reading

1. **Freedom changes the choice, not only the score.** Under auto or allowed, the structured entry wins on four of five diagrams by key, against joint's fixed default choice. Under authored directions it wins only on nested.
2. **The key does not establish that the winner is better.** On network-vlan and org-chart the winning composition has more crossings (74 against 56, 87 against 64) and longer edges (+40 % and +8 %). It wins on the shared-pairs entry, which the key ranks before crossings. Whether this is an improvement depends on the ranking, which is still a judgement.
3. **auto and allowed {lr, tb} are the same search space**, so their results are identical here. They differ once the allowed set differs.
4. The joint layout has no search. The comparison therefore shows the freedom the structured entry adds on top of the joint default, not a fair comparison of equal searches.
