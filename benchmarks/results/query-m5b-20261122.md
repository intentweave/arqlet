# The `query` operation (ADR 0021, M5b): WASM size and the cost of the view mapping

Machine: Apple M3 (macOS, the machine was in use, so the times are single observations on a loaded machine), rustc
1.99.0. Revision: f1fda62 plus the uncommitted M5b change (cargo feature `query`). Measured 2026-11-22.

## Size of the WASM engine, without and with the feature

`cargo build -p arqlet-wasm --target wasm32-unknown-unknown --locked [--features query]`, gzip -9 for the transfer size.

| Profile | without `query` | with `query` | difference |
|---|---|---|---|
| `release` | 12 289 845 B (gzip 2 680 220) | 13 585 068 B (gzip 3 035 790) | +1 295 223 B (+10.5 %), gzip +355 570 B (+13 %) |
| `wasm-size` (the npm artifact) | 6 317 102 B (gzip 1 586 253) | 7 086 031 B (gzip 1 828 847) | +768 929 B (+12.2 %), gzip +242 594 B (+15 %) |

The feature is off by default, so the npm artifact does not change until a release switches it on. The difference is
decypher with its syntax tree, HIR and lowering, plus the executor.

## Cost of mapping an answer onto the view (`"view": true`, ADR 0021 item 10)

`ViewMap::new` is built over the whole source graph per request. Native `fast` profile, one session, the source graph
as the import kept it (`limit` 2000; the session's source graph is the selection, not the whole export: 2 286 and
3 142 nodes), median of 5 runs, default execution limits, queries over all nodes:

| Query | without `view` | with `view` |
|---|---|---|
| `MATCH (n) RETURN count(*)` (2 286 nodes) | 0.6 ms | 3.3 ms |
| `MATCH ()-[r]->() RETURN r.kind, count(*) …` | 1.7 ms | 4.4 ms |
| `MATCH (n {id: 'none'}) RETURN n` | 0.6 ms | 3.3 ms |
| two hops `RETURN count(*)` | 1.9 ms | 4.7 ms |
| the same four on 3 142 nodes | 0.5 – 1.2 ms | 2.4 – 3.0 ms |

The mapping costs 2 – 3 ms here, several times a small answer, and it does not depend on the answer. It therefore stays
opt-in (`view: true`) and is not kept per revision yet; revisit when a host asks for it on every query.

## What the measurement showed about scope

An `import` takes a `limit` of at most 10 000, and the session keeps the selection (and its ancestors) as its source
graph. A query over a session therefore sees that selection, not an export of 100 000 nodes; the answer reports the size
it saw (`graph`). A query over a whole large export needs the host's own copy (the tool `arqlet-query`, or a later
primary store of ADR 0023). A first attempt with a 2-billion step budget on a 10 000-node import ran for over ten
minutes and was stopped: the default limits (20 million steps) exist for that reason, and the default for the number of
steps is still not measured against time.
